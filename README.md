# 竞序 COMPETE — 论文项目前端

面向高校学科竞赛的智能报名检验和成果评价系统。技术栈：Vue 3、Element Plus、GSAP、Canvas、Vite。项目内容依据吴直良的任务书、开题报告与文献综述，外文翻译仅用于确认技术背景；原始 Word 文件未修改。

## 启动

需要 Node.js 22.12+（当前环境已安装 Node.js 22.21）。在本目录执行：

    npm install
    npm run build
    npm start

打开终端显示的本地地址。当前会话已在 http://127.0.0.1:5173 运行生产预览。

也可双击本目录的“启动预览.cmd”。构建文件已包含在 dist 中，已安装依赖时无需再次安装。

开发模式：npm run dev。使用 Rollup watch 重建，完成后手动刷新浏览器。此方式兼容本机对 esbuild 父目录扫描的限制。构建保留未压缩 JavaScript；正式部署前可在正常构建环境启用压缩。

## 页面与交互

- 展示首页：参考站的 #f40c3f / #160000 配色、黑色外框、分格导航、巨型字体、二进制分隔条；鼠标扰动波纹、加载遮罩、标题字符翻滚、星形旋转、滚动揭示、海报悬停、滚动横幅和圆形展开入口。
- 竞赛发现：六个演示方向与原创 CSS 海报；进入管理端可搜索、创建和编辑竞赛名称、期限、阶段与材料要求。
- 学生端：报名表单、选择/拖放文件、类型与大小检查、重复报名拦截、审核进度、作品提交、查看已发布评价、报告导出。
- 教师/管理端：检验队列、五类 OCR 字段编辑、一致性比对、异常标记、带意见的人工复核；示例评价、加权得分、人工改分、成绩发布、审计记录。
- 评价规则：四个维度的非负权重，合计必须为 100%；已生成报告保留当时的权重。
- 数据：localStorage 持久化、报名和评价 CSV 导出、设置中可重置演示数据。
- 响应式：桌面与移动导航；键盘焦点、对话框焦点约束、减少动态效果偏好支持。

## 一条完整演示路径

1. 首页底部 GO 进入报名，或工作台右上角切换“学生端”。
2. 填写报名、选择材料，提交。当前学生演示账号为吴直良，学号 25230810633。
3. 切换“教师 / 管理端” → 报名材料检验 → 查看新报名。
4. 载入示例识别字段，可先保持差异并执行比对，再编辑为申报值、重新比对。
5. 填写复核意见，选择通过或不通过。通过后学生端可提交作品。
6. 学生提交作品后，教师选择作品 → 生成示例评价 → 修改分数和评语 → 保存教师复核 → 发布成绩。
7. 学生在“我的结果”中查看已发布成绩并导出报告。未发布分数不显示。

## 明确的演示边界

这是可运行的前端原型，不是完整后端系统。身份切换用于演示，不提供 JWT 身份验证或服务端权限保护。没有部署 FastAPI、MySQL、PaddleOCR 或大模型。

文件选择支持本地图片预览，但持久化只保存文件名、大小和类型；原文不会上传或保留。OCR 明确载入示例字段，不提取真实图片内容。姓名和学号等已申报字段在前端作去首尾空格后的严格比对；证书名称模糊匹配及图像预处理仍需接入论文后端。

AI 评价固定使用 [85,82,88,84] 的演示分数及示例评语。默认权重 [30,25,25,20] 对应综合得分 84.8；人工把创新性改为 95 后为 87.8。不得将这些分数或数据统计当成真实系统实验结果。

竞赛名称、截止日期、人员、材料与作品均为演示配置。表单日期检查使用客户端当前日期及 Asia/Taipei 时区，因此竞赛过期后需在管理端更新日期才能报名。

## 参考站复刻范围

参考：https://wodniack.dev/ （Antoine Wodniack）。读取了页面、样式和动画结构，并进行浏览器截图观察。首页重建了其主要视觉语言和交互类型，内容替换为论文项目；工作台、竞赛海报和业务流程为本项目新设计。

这不是经过逐帧像素差异验收的完全相同副本：标识、文字、卡片内容、波形算法、海报排列和部分滚动过渡均有改编；原站的所有细节动画、照片墙和物理效果未逐项复制。不能宣称已达到全站逐像素、逐帧一致。

public/fonts 中的 Bigger Display、PP Editorial New、PP Fraktion Mono 字体从参考站公开资源取得用于本地视觉对照，字体权利属于其原作者。对外发布前应确认相应字体许可或替换为获准字体。未复制原作者个人照片或作品视频。

## 后续 FastAPI 对接建议

当前 data.js 是本地数据源，Workspace.vue 中的提交、检验、评价操作是替换服务调用的接入点。建议后端提供：

| 模块 | 建议接口 |
| --- | --- |
| 认证 | POST /api/auth/login、GET /api/me |
| 竞赛 | GET/POST /api/competitions、PATCH /api/competitions/{id} |
| 报名 | GET/POST /api/registrations、POST /api/files（multipart） |
| 检验 | POST /api/registrations/{id}/verification、GET /api/tasks/{id} |
| 人工复核 | PATCH /api/registrations/{id}/review |
| 作品 | GET/POST /api/works |
| 评价 | POST /api/works/{id}/evaluation、PATCH /api/evaluations/{id}/review |
| 发布 | POST /api/evaluations/{id}/publish |

以上为接口规划，并非已实现接口。需在服务端实施身份鉴权、上传校验和持久化；API 密钥只能放在后端。
